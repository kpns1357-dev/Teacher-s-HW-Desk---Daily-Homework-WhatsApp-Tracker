================================================================================
          COMPLETE STEP-BY-STEP GUIDE: HOW THIS APP IS HOSTED & DEPLOYED
================================================================================

This guide explains the entire process of how this website is built, hosted, 
and deployed for free on both GitHub Pages and Vercel.

--------------------------------------------------------------------------------
1. THE CORE IDEA BEHIND HOSTING THIS APP
--------------------------------------------------------------------------------
This project is built using:
- React + Vite (Fast modern frontend library)
- Tailwind CSS (Mobile styling)
- Firebase Firestore (Cloud database for real-time saving)

When you run `npm run build`, Vite packages all code, HTML, CSS, and encrypted 
Firebase logic into a single production folder called:
   `dist/` (contains index.html and assets)

This `dist/` folder can be hosted anywhere for free without needing a paid server!

--------------------------------------------------------------------------------
2. METHOD 1: HOSTING ON GITHUB PAGES (Current Live Method)
--------------------------------------------------------------------------------
GitHub Pages allows you to host websites directly from a GitHub repository for free.

Here is the exact step-by-step process we used:

Step A: Install the `gh-pages` deployment tool
In the project terminal:
   npm install --save-dev gh-pages

Step B: Configure the Base URL in `vite.config.js`
In `vite.config.js`, set:
   base: './'   (or base: process.env.VERCEL ? '/' : './')
This ensures the browser loads styles and scripts properly from relative paths.

Step C: Build the production files
   npm run build
This creates the optimized `dist/` directory.

Step D: Publish the `dist/` folder to the `gh-pages` branch
   npx gh-pages -d dist
What this command does:
1. It takes the contents of your `dist/` folder.
2. It pushes them to a dedicated branch named `gh-pages` on your GitHub repository.

Step E: Enable GitHub Pages in Repository Settings (One-Time)
1. Go to your GitHub repository:
   https://github.com/kpns1357-dev/Teacher-s-HW-Desk---Daily-Homework-WhatsApp-Tracker
2. Click "Settings" (top menu) -> "Pages" (left sidebar).
3. Under "Build and deployment":
   - Source: "Deploy from a branch"
   - Branch: Select "gh-pages" and folder "/ (root)"
   - Click "Save"
4. Within 1-2 minutes, GitHub publishes your live site at:
   https://kpns1357-dev.github.io/Teacher-s-HW-Desk---Daily-Homework-WhatsApp-Tracker/

--------------------------------------------------------------------------------
3. METHOD 2: HOSTING ON VERCEL (1-Click & Lightning Fast)
--------------------------------------------------------------------------------
Vercel is another free hosting platform that automatically rebuilds every time 
you push code to GitHub.

Step A: Create / Login to Vercel
1. Go to https://vercel.com
2. Sign in with your GitHub account: "kpns1357-dev".

Step B: Import the Repository
1. In the Vercel Dashboard, click "Add New..." -> "Project".
2. Select your repository:
   "Teacher-s-HW-Desk---Daily-Homework-WhatsApp-Tracker"
3. Click "Import".

Step C: Configure & Deploy
1. Framework Preset: Vite (Vercel automatically detects this).
2. Root Directory: `./` (leave default).
3. Build Command: `npm run build` (leave default).
4. Output Directory: `dist` (leave default).
5. Click "Deploy".

Step D: Your Live URL
Within 30 seconds, Vercel gives you a free HTTPS link (e.g.,
https://teacher-s-hw-desk.vercel.app).
Every time you push a change to GitHub, Vercel updates automatically!

--------------------------------------------------------------------------------
4. HOW DATABASE & API PRIVACY WORK DURING HOSTING
--------------------------------------------------------------------------------
1. No Cleartext Secrets:
   The Firebase keys are converted into an obfuscated XOR byte sequence inside
   `src/firebase.js`.
2. Anyone inspecting the website in the browser (View Source / Inspect) will
   never see a plain API key, project URL, or authorization header.
3. When any teacher or user interacts with the app, it reads and writes 
   directly to your private Firestore database without requiring any server.
